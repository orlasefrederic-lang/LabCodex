# Android «Блокировать соединения без VPN»: локальная проверка

9 ноября 2026. Android 10/API 29 x86, NetStrazh2.0/code120, режим proxyOFF.
Обычное отдельное приложение `lab.netstrazh.reviewclient`, UID 10119, PID 5978,
один и тот же processNonce во всех трёх фазах. Каждый вызов открывает новые
TCP/UDP-сокеты, не привязывает процесс к сети. Контролируемые назначения:
10.0.2.2:18080/TCP и 10.0.2.2:18081/UDP; личные серверы не используются.

Через штатный экран Android Settings → VPN → Сетевой страж включены
Always-on VPN и Block connections without VPN, системное предупреждение
подтверждено. Исходно обе настройки отсутствовали (`null`), оба переключателя OFF.
Состояния экранов сохранены в XML рядом с логами. Исходники приложения не менялись.

## Три фазы

1. **VPN работает, системная блокировка включена.** Новые TCP/UDP получили
   точные ответы с меткой запроса; оба исходных адреса 10.111.0.1. Android
   сообщает VPN=true, bound=null. [Результат](logs/lockdown-on.json),
   [сервис](logs/lockdown-on-services.txt), [сеть](logs/lockdown-on-connectivity.txt).
2. **Страж принудительно остановлен через `am force-stop lab.netstrazh`.**
   Процесс отсутствует, активного сервиса нет. Настройки при этом сохраняются:
   `always_on_vpn_app=lab.netstrazh`, `always_on_vpn_lockdown=1`.
   Оба новых подключения отклонены Android с **EACCES (Permission denied)**,
   payload не получен; активная сеть для клиента null. Это не ожидание тайм-аута
   неработающего сервера. [Результат](logs/lockdown-off.json),
   [проверка процесса/настроек](logs/lockdown-off-state.json),
   [сервис до](logs/lockdown-off-services-before.txt) и
   [после](logs/lockdown-off-services-after.txt).
3. **Обратный контроль:** оба системных переключателя выключены, Страж
   остаётся остановленным. Тот же процесс клиента получил точные TCP/UDP-ответы
   напрямую с адреса 10.0.2.16. Ответчики всё это время работали.
   [Результат](logs/lockdown-control.json), [экран](logs/lockdown-restored.xml).

После проверки возвращены исходные отсутствующие значения обеих настроек:
[восстановление](logs/lockdown-restored-state.json). Сводка с проверками трёх
фаз: [lockdown-summary.json](logs/lockdown-summary.json).

## Границы

Подтверждена системная блокировка новых TCP/UDP **при остановленном VPN**
для этого обычного UID и LAN IPv4 на этом эмуляторе. Это поддерживает
рекомендацию использовать системный режим, когда выход без VPN недопустим.
Тест не доказывает каждую гонку мгновенного старта/rebuild, работу всех
направлений/UID/IPv6/прошивок, а также совместную передачу через v2rayNG
именно в режиме lockdown. Нормальная связка с v2rayNG проверялась отдельно,
при выключенном lockdown. Настройку телефона и её совместимость с его
proxy-конфигурацией следует проверять отдельно.

Тест не использовал скрытый API или изменение разрешений приложения.
Запуск клиента: [probe-client.py](probe-client.py); исходники клиента:
[client-probe](client-probe). UI-проверки выполнялись после завершения
instrumentation, чтобы не конфликтовать за UiAutomation.
